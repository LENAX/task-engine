# Release Note - v1.0.16

**发布日期**: 2026-03-11

## 概述

v1.0.16 主要包含 **Realtime 可观测性**、**DataHandler 失败重试**，以及 **多订阅者广播（SPMC）与 WAL** 相关能力：data.processed 空处理器消除 watermill 日志噪音、E2E 结束时打印入库数据量、StreamProcessor 支持配置最大重试次数并在失败时重新入队。

---

## 增强 (Enhancements)

### 可观测性

- **data.processed 空处理器**：为 `data.processed` 主题注册空处理器，避免 watermill 在无订阅者时打印 "No subscribers to send message"。
- **E2E 入库数据量**：每个 Realtime E2E 测试结束时通过 `t.Cleanup` 打印 `[E2E] 入库数据量: N` 或 `N/A (本测试无 DB 写入)`，便于排查与对比。

### DataHandler 失败重试

- **DataHandlerMaxRetries**：`ContinuousTaskConfig` 新增 `DataHandlerMaxRetries`（默认 0）。大于 0 时，DataHandler 返回 Failed 会将当前消息以 `bufferItemWithRetry` 重新入队，并限制最大重试次数；超限或入队失败（缓冲区满）则丢弃并记错误。
- **WithDataHandlerMaxRetries**：`RealtimeTaskBuilder` 新增 `WithDataHandlerMaxRetries(maxRetries int)`，用于配置上述最大重试次数。
- **行为**：0 = 不重试（与旧版一致）；设为 3 表示单条消息最多执行 4 次（1 次初始 + 最多 3 次重试）。

### 多订阅者广播与 WAL（SPMC）

- **Subscriber 按 code 过滤**：订阅者支持 `FilterCodes`，广播与 WAL 回放时仅向订阅了对应 code 的订阅者推送。
- **WAL 与 Badger 实现**：`WalStore` 接口、Badger 实现及回放未确认记录逻辑，支持实例重启后补发。
- **Tushare Mock 与 E2E**：Tushare 风格 WebSocket Mock 服务、批量写 SQLite + Console 的 E2E，以及断线恢复、DB 写失败重试用例；文档与示例（`examples/realtime_demo/`）更新。

---

## 升级建议

- 若希望 DataHandler 写入失败时由框架自动重试，在构建 StreamProcessor 时增加 **WithDataHandlerMaxRetries(3)**（或其它正整数）；不设置则保持原行为（失败即丢弃该条）。
- 使用多订阅者且需按 code 过滤时，在 Workflow 的 StreamProcessor 配置中设置 **SubscriberFilterCodes**，并在 Builder 侧使用 **WithSubscriberFilterCodes(codes)**。
